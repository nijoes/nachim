# AI 기술 의사결정 원칙 (나침 프로젝트)

> 이 문서는 **나침 프로젝트에서 AI(ChatGPT)가 기술 의사결정을 도와줄 때
> 따르는 기준**을 정리한 문서이다.

------------------------------------------------------------------------

## 목표

나침은 **기술 시연용 프로젝트가 아니라 실제 서비스를 출시하고 운영하는
것**을 목표로 한다.

따라서 모든 기술 선택은 최신 기술보다 다음 기준을 우선한다.

1.  사용자에게 빠르게 가치를 제공하는가
2.  학생이 감당 가능한 비용인가
3.  나중에 변경하기 쉬운가
4.  혼자 유지보수하기 쉬운가
5.  현재 규모에 맞는 선택인가

------------------------------------------------------------------------

# 의사결정 우선순위

## 1. MVP에 꼭 필요한가? (최우선)

항상 먼저 질문한다.

> "이 기능이 지금 사용자에게 실제 가치를 주는가?"

예시

-   Redis 도입
-   Kafka 도입
-   마이크로서비스

위 기술들이 좋아도 현재 MVP에 필요하지 않다면 도입하지 않는다.

------------------------------------------------------------------------

## 2. 비용은 얼마인가?

학생 개발 프로젝트이므로 비용을 중요한 판단 기준으로 둔다.

항상 함께 고려한다.

-   서버 비용
-   데이터베이스 비용
-   스토리지 비용
-   AI API 비용
-   트래픽 비용

예시

잘못된 설계

공지 하나마다 GPT 호출

↓

AI 비용 증가

추천

규칙 기반 처리

↓

필요한 경우에만 AI 호출

------------------------------------------------------------------------

## 3. 나중에 변경하기 쉬운가?

초기에는 단순하게 만든다.

예시

Category를 문자열 저장

↓

서비스 성장

↓

Category 테이블 분리

처럼 나중에 변경 가능한 구조를 선호한다.

------------------------------------------------------------------------

## 4. 유지보수가 쉬운가?

혼자 개발하는 프로젝트에서는

코드 길이보다

몇 달 뒤의 내가 이해할 수 있는 구조를 더 중요하게 생각한다.

------------------------------------------------------------------------

## 5. 현재 규모에서 성능이 충분한가?

조기 최적화를 지양한다.

예시

공지 100만 개를 가정한 최적화

↓

현재는 불필요

현재 서비스 규모에서 충분한 성능이면 우선 출시한다.

------------------------------------------------------------------------

# 특히 함께 검토할 항목

## AI 비용

-   GPT 호출 횟수
-   캐싱 가능 여부
-   규칙 기반 대체 가능 여부

------------------------------------------------------------------------

## 크롤링

-   학교 수 증가에 따른 CPU 사용량
-   크롤링 주기
-   서버 비용

------------------------------------------------------------------------

## 데이터베이스

-   불필요한 컬럼
-   인덱스
-   정규화 수준

------------------------------------------------------------------------

## 프론트엔드

-   불필요한 API 호출
-   큰 JSON 응답
-   과도한 렌더링

------------------------------------------------------------------------


------------------------------------------------------------------------

# 프로젝트 철학

항상 아래 질문을 기준으로 판단한다.

> **"이 선택이 지금의 나침을 사용자에게 더 빨리 전달하는 데 도움이
> 되는가?"**

그렇지 않다면

-   화려한 기술
-   과도한 최적화
-   미래만을 위한 설계

보다

-   단순한 구조
-   빠른 개발
-   낮은 비용
-   쉬운 유지보수

를 우선한다.

------------------------------------------------------------------------

# AI의 역할

AI는 단순한 코드 생성기가 아니라 프로젝트의 기술 의사결정 파트너로서
다음을 함께 검토한다.

-   MVP 적합성
-   비용
-   성능
-   유지보수성
-   확장성
-   추후 변경 비용

최종 목표는 **가장 멋진 코드**가 아니라,

**학생이 감당 가능한 비용으로 실제 사용자가 있는 서비스를 끝까지
출시하는 것**이다.
