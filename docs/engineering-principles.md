# Engineering Principles

> Last Updated: 2026-07-08

## 목적

이 문서는 **나침(Nachim)** 프로젝트의 기술적 의사결정 기준을 정의한다.

나침은 **최고의 기술을 보여주는 프로젝트**가 아니라,

**학생에게 가장 큰 가치를 가장 빠르게 제공하는 서비스**를 만드는 것을 목표로 한다.

모든 기술 선택은 아래 원칙을 따른다.

---

# 1. 핵심 경쟁력은 직접 개발한다.

우리가 직접 만들어야 하는 것은

- 데이터
- 데이터베이스 구조
- 비즈니스 로직
- 추천 로직
- 분석 로직

이다.

이 부분이 나침의 경쟁력이며,
외부 서비스에 의존하지 않는다.

---

# 2. 공통 기능은 적극적으로 외부 서비스를 활용한다.

나침의 경쟁력이 아닌 기능은
직접 구현하지 않는다.

예시

- AI → OpenAI API
- 인증 → Clerk / Supabase Auth
- 파일 저장 → Cloudflare R2 / AWS S3
- 크롤링 → Playwright
- ORM → SQLAlchemy
- Scheduler → APScheduler

시간을 절약하여
핵심 기능 개발에 집중한다.

---

# 3. 데이터는 반드시 우리가 소유한다.

가장 중요한 원칙이다.

다음 데이터는 항상 나침이 직접 관리한다.

- PostgreSQL Database
- 크롤링 원본 데이터
- 사용자 행동 데이터
- 분석 결과

외부 AI는 사용할 수 있지만

데이터는 반드시 우리 DB에 저장한다.

---

# 4. 원본 데이터는 절대 버리지 않는다.

AI는 계속 발전한다.

현재의 분석 결과보다

미래의 AI가 더 정확할 가능성이 높다.

따라서

원본 데이터(content)는 항상 보관한다.

필요하면 언제든

다시 분석(Re-processing)할 수 있도록 설계한다.

---

# 5. MVP에서는 단순함을 우선한다.

MVP의 목표는

동작하는 서비스를 만드는 것이다.

처음부터

- 과도한 정규화
- 복잡한 아키텍처
- 과도한 추상화

를 하지 않는다.

필요해질 때 확장한다.

---

# 6. 구조는 언제든 변경할 수 있도록 만든다.

DB 구조는 고정된 것이 아니다.

Alembic Migration을 이용하여

점진적으로 개선한다.

처음부터 완벽한 구조를 만드는 것보다

변경하기 쉬운 구조를 만든다.

---

# 7. 보안은 타협하지 않는다.

개발 속도를 위해

보안을 희생하지 않는다.

최소한 다음 사항은 반드시 지킨다.

- API Key 환경변수 관리
- 비밀번호 해싱
- SQL Injection 방지
- 인증 및 권한 관리
- HTTPS 사용

---

# 8. 기술보다 개발 속도를 우선한다.

학생 1인 개발자로서

가장 중요한 자원은 시간이다.

비용이 조금 증가하더라도

개발 기간을 크게 줄일 수 있다면

검증된 서비스를 적극 활용한다.

---

# 9. 외부 서비스는 언제든 교체 가능하도록 만든다.

외부 API를 직접 호출하지 않는다.

반드시 내부 Service Layer를 둔다.

예시

User

↓

FastAPI

↓

AIService

↓

OpenAI API

나중에

Claude

Gemini

자체 모델

등으로 쉽게 교체할 수 있도록 설계한다.

---

# 10. 데이터 품질이 기술보다 중요하다.

좋은 AI보다

좋은 데이터가 더 중요하다.

좋은 UI보다

좋은 데이터가 더 중요하다.

나침의 장기 경쟁력은

학생들의 실제 데이터이다.

모든 개발은

데이터 품질을 높이는 방향으로 진행한다.

---

# 기술 선택 기준

새로운 기술을 도입할 때는
항상 아래 순서대로 판단한다.

1. 보안에 문제가 없는가?
2. 비용이 감당 가능한가?
3. 개발 시간을 크게 줄여주는가?
4. 나중에 쉽게 교체 가능한가?
5. 데이터는 우리가 직접 소유하는가?

모든 조건을 만족한다면
외부 서비스를 적극 활용한다.

---

# 우리가 집중해야 하는 전문성

나침에서 가장 중요한 전문성은

- 데이터 설계
- SQL
- 데이터 분석
- Python
- FastAPI
- 보안 기초

이다.

기술 스택보다

데이터를 이해하는 능력이

나침의 가장 큰 경쟁력이 된다.

---

# 한 줄 원칙

> 핵심 경쟁력은 직접 만들고, 공통 기능은 적극적으로 활용하며, 데이터는 반드시 우리가 소유한다.
